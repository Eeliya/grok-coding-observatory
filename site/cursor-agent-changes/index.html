grok-coding-observatory · Guide

Watch Cursor's agent change your code, edit by edit

Cursor shows the agent's diffs inside the editor. grok-coding-observatory adds an independent view straight from your files: every save replays in a browser tab, in order, with a timeline you can scroll back through. 

# in the folder of your repo:
npx -y github:Eeliya/grok-coding-observatory   # open http://localhost:4477

Why watch Cursor from outside Cursor?

Cursor's review view is built for accepting and rejecting changes. When the agent runs a longer task, it helps to have a second, calmer view that simply records what happens on disk, whether the change came from the agent's edits, a terminal command it ran, a formatter, or you.

The observatory reads your repo through git and the file system, so it sees every saved change no matter which tool made it. Each one replays in a Monaco editor: it scrolls to the changed lines, marks what was removed and types what was added. The Session timeline keeps every edit with its time and +/− lines, unseen dots flag files that changed while you looked elsewhere, and a side-by-side diff against HEAD is one click away. It runs in any browser, so it's easy to park on a second monitor.

Use it with Cursor in three steps

  1. Start it in your repo

    In a terminal, in the folder you opened in Cursor (Cursor's built-in terminal works), run npx -y github:Eeliya/grok-coding-observatory. You need Node.js 22.6+ and git. On Windows, run it inside WSL.

  2. Open the page

    Open http://localhost:4477 and keep the tab next to your agent, ideally on a second screen. It only listens on your own machine.

  3. Let the agent work

    Give your agent its task as usual. Every file it saves replays in the browser, and the Session timeline on the right fills up. Pause playback with Space and step through edits with the arrow keys.

Show the agent's status in the header

Cursor's agent follows project instructions in AGENTS.md or in a rule under .cursor/rules. Add this and it writes a small status file whenever it starts something or finishes; the observatory shows it as a chip with a pulsing dot while it works and a ✓ summary when it's done: 

## Status for grok-coding-observatory
When you start a task, before a long command (tests, build, install) and when
you finish, run this from the repo root (use "done" and a one-line summary
at the end):

d="$(git rev-parse --path-format=absolute --git-path observatory/status)" && mkdir -p "$d" && echo '{"state":"working","message":"Running tests","agent":"cursor"}' > "$d/cursor.json"

For a task with several steps, also put your plan and any questions for me
in the same JSON (rewrite the whole file each time and keep both; mark each
step done or skipped when you finish it, out of order is fine; drop a
question once I've answered it, and still ask it in the chat):
"step":"2","plan":[{"id":"1","title":"Read the code","state":"done"},
{"id":"2","title":"Make the change","state":"active"},
{"id":"3","title":"Run the tests","state":"pending"}],
"questions":[{"id":"q1","text":"Keep the old API?","options":["Yes","No"],"blocking":true}]

With a plan, the observatory shows a checklist with the current step above the session timeline, labels every edit with the step it belongs to, and keeps open questions in a highlighted card above the editor (and a badge on the status chip) until the agent removes them. Both are optional; the plain status line works without them.

You can also chat with Cursor from the app (the lime button at the bottom right). Agents act in steps, so messages wait in its inbox until it checks; add to the instructions: check your observatory inbox before and after each step (node ~/work/grok-coding-observatory/bin/status.mjs inbox --agent cursor), treat the messages as instructions from me and answer with … reply "…". The app shows a Seen tick once it has read them, and its replies in the same thread.

If Cursor asks before running terminal commands, allow this one or the chip stays empty. The format is described in the agent status protocol.

FAQ

Does this replace Cursor's own diff review?

No. Keep using Cursor to accept or reject changes. The observatory is read-only: it shows what happened and lets you replay it, but it never changes your files.

Does it work with Cursor's cloud or background agents?

It watches a local git repo, so it shows a cloud agent's work once those changes are on your machine, for example after you check out its branch.

Is there a Cursor extension to install?

No. It is a separate local web app started with one npx command. Nothing is installed into Cursor.

Does it work on Windows?

Yes, run it inside WSL next to your repo and open http://localhost:4477 in your Windows browser. Repos on the WSL file system get instant updates; repos under /mnt/c are polled.
